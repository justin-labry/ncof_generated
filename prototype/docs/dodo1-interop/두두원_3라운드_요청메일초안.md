## 4. 확인 요청 — `14_e` QoS UDP 수신 측 (`192.168.1.182:26321`)

오늘 17:49:51 `14_e` 수신 직후 아래와 같이 UDP 가 발사된 것을 확인했습니다.

```
QOS UDP send Success target=192.168.1.182:26321 size=128
QOS UE1 imsi=001010070000101 gbrDl=5.000000    mbrDl=10.000000
QOS UE2 imsi=001010070000103 gbrDl=1000.000000 mbrDl=1000.000000
QOS UE3 imsi=001010070000102 gbrDl=0.000000    mbrDl=0.000000
QOS UE4 imsi=001010070000104 gbrDl=1000.000000 mbrDl=1000.000000
```

9월 18일(포트 5555)에는 이 목적지에 수신자가 없었는데, 이번에는 26321 에 수신 소켓이 있고 패킷도 읽혀
나갔습니다. 실제 QoS 에 적용되는지에 따라 의미가 크게 달라져서 네 가지를 여쭙니다.

1. 26321 을 받는 쪽이 **UPF 이고, 받은 값을 실제 세션 QoS 에 적용**하는지요?
2. `gbr_dl`/`mbr_dl` 의 **단위**는 무엇인지요? 저희는 `"5.0 Mbps"` 처럼 단위를 붙여 보내는데,
   `std::stod` 에서 단위가 빠져 숫자 `5.0` 만 들어갑니다. UPF 가 이를 Mbps 로 읽지 않으면 값이 10⁶배 달라집니다.
3. **`0` 의 의미**(차단 / 무제한 / 미적용)는 무엇인지요? 오늘 `imsi-…102`(UE2_GNB2) 슬롯에 `0/0` 이 실렸습니다.
   현재 부하에서는 이 UE 의 코어 카운터에 변화가 보이지 않지만, 오늘 세팅하신 VLC 스트리밍이 이 UE 를
   거친다면 영향이 있었는지 확인 부탁드립니다.
4. 적용된 값의 **유효기간과 해제 방법**은 어떻게 되는지요? UDP 패킷에는 유효기간 필드가 없고, NCOF 는 판정이
   바뀔 때만 `14_e` 를 보내므로(현재 설정에서는 기동 후 1회), 한 번 적용된 값이 언제까지 유지되는지 알고 싶습니다.

현재는 UDP 발사가 실패하거나 UE 4개가 다 차지 않아도 SBI 응답이 `200` 이라, 저희 쪽에서는 적용 여부를
알 수 없습니다. 가능하시면 적용 결과를 로그로 남기시거나, 응답 본문에 발사 여부(예: `udp_sent`,
`fill_count`)를 실어 주시면 좋겠습니다 (이전에 요청드린 "제어 결과 확인 수단" 의 연장입니다).
