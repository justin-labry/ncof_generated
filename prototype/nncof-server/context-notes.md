# 컨텍스트 노트

- 2026-08-05. 기존 구독과 Notify 데이터는 `SubscriptionManager`와 `NotificationDataStore`의 메모리에만 존재한다.
- 2026-08-05. 재시작 복구 시 저장된 하위 NF 구독 ID를 신뢰하지 않고 해지를 시도한 후 새로 구독한다. NCOF 재시작 중 하위 NF가 유지될 수 있어 중복 Notify를 줄이기 위함이다.
- 2026-08-05. 자동 재시도, 보관 기간, 관계형 데이터베이스 전환은 이번 범위에서 제외한다.
- 2026-08-05. `JsonStateStore`는 임시 파일을 작성한 뒤 `os.replace`로 원자적으로 상태 파일을 교체한다. 손상 파일은 `.corrupt` 확장자로 보존한다.
- 2026-08-05. FastAPI lifespan이 기동 시 저장 구독을 복원하고, 종료 시 하위 NF 구독을 유지한 채 분석 태스크와 HTTP 클라이언트만 정리한다.
- 2026-08-05. `data/ncof_state.json`과 임시 및 손상 파일은 런타임 산출물이므로 Git 추적에서 제외한다.
- 2026-08-05. 새 영속성 테스트 3건은 통과했다. 전체 기존 테스트는 자동 생성 테스트 데이터에 정의되지 않은 Python `null` 식별자가 있어 4건 실패했다.
- 2026-08-05. 상태 파일에 Pydantic 모델의 datetime이 포함될 수 있으므로 `JsonStateStore`에서 `jsonable_encoder`로 모든 저장 상태를 변환한다.
- 2026-08-05. 복원 경로에서도 최초 요청의 NF ID로 PCF 또는 RICF를 계산해 최초 NF에서 NCOF로 향하는 `SUBSCRIBED` 관계를 재구성한다.
- 2026-08-05. Windows에서 대상 상태 파일이 잠시 잠긴 경우를 위해 고유 임시 파일을 사용하고 `os.replace`를 제한 횟수 재시도한다.
